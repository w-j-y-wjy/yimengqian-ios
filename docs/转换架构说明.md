## 1. 源码分析结论（安卓工作区扫描）

### 1.1 应用本质

《一梦千年》是一款以中华古典文化为主题的沉浸式体验 App（移动应用比赛作品）。其核心工程 `app-project` 是一个 **React 18 + Vite + Capacitor** 的 H5 原型：

- **页面 = 设计稿截图 + 可点热区（Hotspot）**：全部 25 个页面均由 `src/pages/*.tsx` 渲染 `ImageScreen` 组件 —— 整屏展示设计稿 PNG（`public/screens/`），上面覆盖透明热区按钮（百分比坐标，来自 `src/config/screens.ts` + `src/config/hotspot-overrides.json`）。
- **交互 = 热区动作（Action）**：点击热区执行 15 种动作（navigate / back / toast / storage / toggleStorage / conditionalJump / checkAnswer 等），写入 `localStorage` 驱动流程状态。
- **视觉 = 设计稿本身**：底部导航栏、页面元素全部绘制在截图内（`BottomNav.tsx` 为死代码，未被引用）。
- **内容数据**：`src/data/*.ts` 提供朝代、人物、诗词、古物、活动、印章、对话等静态内容（原型阶段仅少量被热区 Toast 引用，是后续原生页面与状态层的素材）。

### 1.3 状态模型（AppContext + localStorage）

- 全局状态 `AppContext`：昵称（梦客·苏蘅）、身份（江南游学者）、朝代、性格标签、文化值 1200、雅集值 680、花瓣 12、等级 4、诗词/器物/人物计数、印章列表、收藏、已完成任务、对话进度、飞花令进度、生成卡片等；整体 JSON 持久化到 `yimeng-qiannian-state`。
- 离散键（`appStorageKeys.ts` 共 49 个）：onboardingComplete、preferenceScene/Content/Dynasty/Mood、dialogueTopic、teaDialogueCompleted、cultureValue、stampDongpo、sushiLetter、jiangxueStyle、favoriteJiangxue、selectedImagery、poetryCardStyle/Layout/Seal、favoriteArtifact、feihualingAnswer、feihualingCompleted、petalCount、favoriteFilter 等。
- 特殊页面逻辑：
  - `Splash`：`conditionalJump` —— 若 `onboardingComplete=true` 直达 /home，否则进引导；`?reset=1` 清空全部键。
  - `TaskReward`：进入即结算奖励一次（文化值+50、东坡知音印章、苏轼来信、汴京进度 75%）。

## 2. 转换策略决策

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 原生重绘 25 页 | 用 SwiftUI 组件重画每个页面 | 工作量大、视觉必然偏离设计稿（竞品评审以设计稿为准），且已有 `Yimengqian_Snai` 草案证明此路会"看起来不像原版" |
| B. 忠实移植（热区引擎） | SwiftUI 引擎渲染设计稿截图 + 透明热区层，逐一复刻 15 种动作与全部状态键 | **采用**：100% 功能与视觉对齐、代码面小、可离线编译校验 |

**选择 B：图像热区引擎的忠实端口。** 原应用本身就是"设计稿 + 热区"的交互原型，最忠实的转换就是把这个交互模型原样搬到 iOS：SwiftUI 原生外壳（路由栈、Toast、转场动画、状态持久化）+ 全部设计稿资源 + 全部热区配置（含校准覆盖）+ 完整数据层（为后续原生页面留好素材）。

> 注：工作区内另有早期草案 `一梦千年_iOS代码/Yimengqian_Snai`（纯 SwiftUI 原生重建，无 .xcodeproj、页面与设计稿不符），作为"原生重绘"路线的前车之鉴记录于此，未直接复用。

### 4.2 状态层（Agent B）

```swift
// StorageKeys.swift —— 对应 appStorageKeys.ts 全部 49 键（字符串常量）

// AppStore.swift —— ObservableObject；语义对齐 AppContext + localStorage
final class AppStore: ObservableObject {
    // —— 离散键语义（与 Web localStorage 完全一致）——
    func string(_ key: String) -> String?      // getItem
    func setString(_ key: String, _ value: String)  // setItem
    func remove(_ key: String)                 // removeItem
    func setIfAbsent(_ key: String, _ value: String) // 仅当不存在时写入
    func toggle(_ key: String) -> Bool         // setItem/removeItem，返回当前是否为 true
    func bool(_ key: String) -> Bool
    func incrementInt(_ key: String, by: Int = 1) -> Int
    // —— 整体快照（对应 yimeng-qiannian-state JSON）——
    @Published var snapshot: AppSnapshot        // Codable，全字段，载入/保存
    func resetAll()                            // 清空全部键并恢复默认快照
}
```

### 4.3 引擎层（Agent C1）

```swift
// Router.swift
final class Router: ObservableObject {
    @Published private(set) var stack: [ScreenConfig]
    func push(_ screen: ScreenConfig)          // 入栈（转场动画）
    func back()                                // 出栈；栈底时无操作
    func navigate(route: String)               // route → ScreenConfig（未知路由忽略）
    func jump(to screen: ScreenConfig)         // 替换栈顶（用于 conditionalJump 直达 /home）
    var top: ScreenConfig? 
}

// ToastCenter.swift
final class ToastCenter: ObservableObject { @Published var message: String?; func show(_ msg: String) }

// ActionExecutor.swift —— 15 种动作，逐一对齐 ImageScreen.executeAction
final class ActionExecutor {
    init(store: AppStore, router: Router, toast: ToastCenter)
    func execute(_ action: HotspotAction, screenID: String)
}
```

## 5. 构建方式

1. 需要 macOS + Xcode 15+（最低 iOS 15.0）。
2. 打开 `Yimengqian.xcodeproj`，选择 Team（签名），选择 iPhone 模拟器/真机运行。
3. 首次打开若 Assets 目录为空图标显示为默认，可在 Xcode 中替换 AppIcon。
4. `tools/` 下的生成脚本仅供再生成使用（`node tools/generate_screens_swift.mjs`、`node tools/generate_pbxproj.mjs`），已生成的产物直接可用。
