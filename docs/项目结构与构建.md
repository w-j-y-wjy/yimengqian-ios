# 项目结构与构建

> 这份文档回答两个问题：**代码放哪**、**怎么验证它没编译坏**。

## 一、目录结构

仓库根 = `ios/`（只包含 iOS 工程，不含安卓/鸿蒙与参赛材料）。

```
ios/
├── .github/workflows/
│   ├── ios-build.yml        # 主证据：macOS 上编译 + 模拟器冒烟 + 截图
│   └── static-check.yml     # 免费快检：结构一致性（不编译）
├── docs/                    # 文档（本文件、转换架构说明）
├── scripts/
│   ├── static-check.mjs     # 结构检查，本地/CI 通用（Windows 也能跑）
│   └── build-sim.sh         # 老 Mac（Xcode 14.2）关键节点构建
├── tools/                   # 两个 .mjs 生成器（慎用，见第三节）
├── Yimengqian/
│   ├── Yimengqian.xcodeproj/
│   ├── build.sh             # 本地构建脚本（模拟器/真机/归档）
│   └── Yimengqian/          # 源码根
│       ├── App/             # 入口 + 根视图
│       ├── Config/          # ScreensConfig（自动生成）、StorageKeys
│       ├── Engine/          # Router / ActionExecutor / ToastCenter
│       ├── Models/          # DomainModels / ContentData
│       ├── State/           # AppStore
│       ├── Utilities/       # Theme / Helpers
│       ├── Views/           # HotspotScreenView（渲染引擎）
│       ├── Content/         # Screens 25 张设计稿 + Reference 参考图
│       ├── Assets.xcassets/ # 图标与启动色
│       └── Info.plist
└── README.md                # 使用说明（面向人）
```

**新增源码的落位约定**（Phase 2–5 会新增大量文件，先定规矩）：

| 要加的东西 | 放哪 |
|---|---|
| 原生叠层视图（每屏一个） | `Yimengqian/Views/Native/` |
| 选择态、派生数值等状态逻辑 | `Yimengqian/Engine/` 或 `Yimengqian/State/` |
| AI 能力（识别/语音/生成/对谈） | `Yimengqian/AI/` |
| 新增配置数据 | `Yimengqian/Config/` |

## 二、三条验证通道

| 通道 | 跑在哪 | 耗时/成本 | 什么时候用 |
|---|---|---|---|
| **① iOS Build**（主证据） | GitHub Actions `macos-15` · Xcode 16.x | ~5–8 分钟 macOS 分钟 | 每次推送到 `main`；动手改代码前必须先绿一次 |
| **② 结构检查** | GitHub Actions `ubuntu-latest` | ~20 秒，**零 macOS 分钟** | 每次推送/PR 自动跑；本地也可 `node scripts/static-check.mjs` |
| **③ 老 Mac 构建** | 你的 Monterey + **Xcode 14.2** | 手工，1–3 分钟 | 只在关键节点（阶段收尾）确认 14.2 仍能编译 |

### 为什么主证据不是本地 Mac

GitHub Actions 现役 macOS 镜像只剩 macOS 15 / 26（Xcode 16 / 26），
**Xcode 14.2 已经不在任何 runner 镜像里**；而本机是 Windows、老 Mac 只有 14.2。
两边都拿不到「现代工具链」，所以只能把 CI 当作唯一稳定的编译门。

### 工具链落差要注意

| | CI（主） | 老 Mac（副） |
|---|---|---|
| Xcode | 16.x | 14.2 |
| Swift 编译器 | 5.9+ / 6 | 5.7 |
| iOS SDK | 18+ | 16.2 |

结论：**新代码只能用 Swift 5.7 就有的语法**（不要用 `if`/`switch` 表达式、`@Observable`、
宏、参数包等 5.9+ 特性），否则 CI 绿而老 Mac 红，或反之。
API 侧统一守住 **iOS 15 可用**这条线（不要用 iOS 16+ 才有的 API）。

### 本地怎么跑

```bash
# 结构检查（Windows / macOS 都可以）
node scripts/static-check.mjs            # 常规
node scripts/static-check.mjs --strict   # Phase 1 修完后：已知缺口也判失败

# 老 Mac 上（macOS Monterey + Xcode 14.2）
chmod +x scripts/build-sim.sh
./scripts/build-sim.sh                   # 默认 iPhone 14
```

## 三、三条硬规矩

1. **绝不重跑 `tools/generate_pbxproj.mjs`** —— 它认的是 `Resources` 目录名，
   而磁盘上早已改名 `Content`，重跑会把整个资源目录从工程里丢掉。
   确实要跑，先在副本上验证，别对真工程直接跑。
2. **新增 `.swift` 必须同时加进 pbxproj**（`PBXBuildFile` / `PBXFileReference` / `Sources` 三处）。
   忘加的症状是「文件明明在，却说找不到符号」——`static-check` 的 `pbxproj.sources` 会拦住它。
3. **不删文件**。本轮明确不清理任何现有内容；要删先列清单经确认。
   想瘦身也只能改配置与引用，不动磁盘。

## 四、当前有意缺失的东西

| 缺什么 | 为什么 | 影响 |
|---|---|---|
| `ExportOptions.plist` | 归档导出才需要 | `build.sh archive` 会失败，模拟器构建不受影响 |
| `DEVELOPMENT_TEAM` | 需要你的开发者账号 | 真机安装需在 Xcode 里手动选 Team |
| 测试 target | 原工程没有 | CI 只能做「编译 + 启动」冒烟，不做单元测试 |
| `PrivacyInfo.xcprivacy` | Phase 1-4 才补 | App Store 归档会收到 ITMS-91053 类告警 |
